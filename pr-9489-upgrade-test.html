What PR #9489 Achieves

The Fix: Detects CREATE operations on Kubernetes Services using ResourceVersion field and seeds the NLB annotation only during CREATE, not UPDATE.

Code Pattern (service.go lines 36, 79-81)
// Line 36: Detect CREATE vs UPDATE isCreate := svc.ResourceVersion == "" // Lines 79-81: Seed annotation ONLY on CREATE if isCreate && hcp.Spec.Platform.Type == hyperv1.AWSPlatform { svc.Annotations[AWSNLBAnnotation] = "nlb" }

Why This Works

  • ResourceVersion is empty string ONLY on Service creation
  • ResourceVersion is non-empty on all subsequent updates
  • AWS ValidatingAdmissionPolicy BLOCKS UPDATE operations that modify annotation
  • AWS ValidatingAdmissionPolicy does NOT match CREATE operations
  • Result: Annotation seeded at CREATE, never modified on UPDATE, VAP never triggered

Production Impact

Before PR #9489: Cluster upgrades fail when CPO tries to add NLB annotation during UPDATE, triggering AWS VAP block

After PR #9489: Cluster upgrades succeed, NLB annotation preserved, zero AWS policy violations
